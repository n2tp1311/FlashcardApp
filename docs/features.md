# Feature Stories

## Localization (English / Vietnamese)
- Preferences modal has an English / Tiếng Việt language toggle; selection persisted server-side via `/api/auth/preferences` and cached in `localStorage["fc-language"]`/`fc-preferences` for instant load before the network round-trip
- Custom lightweight i18n system (no external library, no build step): `TRANSLATIONS.{en,vi}` dictionaries, `t(key, vars)` lookup with English fallback and `{var}` interpolation, `applyI18n(root)` DOM-walker driven by `data-i18n`/`data-i18n-placeholder`/`data-i18n-title`/`data-i18n-aria` attributes
- Plurals: `t(key, {n})` uses a `key_one` string when `n` is 1 (English only; Vietnamese has no plural forms), so counts read "1 card" / "2 cards". Durations use translated `unit.*` strings everywhere ("10 min" / "10 phút", "1h 5m" / "1 giờ 5 phút"), and study time under a minute shows seconds
- Icon-preserving translation: `applyI18n` updates only the last text node of an icon+label button (rather than clobbering `innerHTML`), so inline SVG icons survive a language switch without needing every button label wrapped in a `<span>`
- Every screen, modal, and dynamically-generated string (search results, share invite list, validation messages and toasts, MCQ distractor fields, relative-time labels, difficulty/format badges) is wired through `t()` — covers the full app, not just static markup
- Server errors a user can cause carry a stable `code` (`invalidCredentials`, `rateLimited`, `cannotInviteSelf`, …) that the client translates via `error.<code>`, falling back to the server's English text for anything else; connection failures read "Network error"
- Explicitly out of scope: user-authored content (card text, class/lesson names, `cls.icon`), uncoded server error strings passed through verbatim, and the AI-extraction-prompt text (instructional copy meant for an external AI tool, not the app's own UI)
- Remaining gaps closed from the 10-agent UX audit: card-select-toolbar counter (`"N selected"`), the Generate Link / Invite-by-Name-or-Email share modal headings, and the True/False result badge (`"✓ True"`/`"✓ False"`) now go through `t()` instead of hardcoded English

## UI / Design
- Logo is a hand of three flashcards whose front card carries three linked ideas (`client/logo.svg`, regenerated `icon-192/512.png` and `apple-touch-icon.png`); it shares its dark tile and colours with the KnowledgeApp logo (a book with ideas rising from it), so the sibling apps read as a pair
- All emoji UI-chrome icons (buttons, headers, dropdown items, empty-state illustrations, sort-direction/kebab/close controls) replaced with a single minimalist SVG icon set (feather-style: `stroke="currentColor"`, `stroke-width="2"`, rounded caps) for visual consistency across the whole app
- `svgIcon()` + `ICON_*` constants in `client/app.js` provide reusable icons for dynamically-generated list rows (class/lesson/card edit/delete/archive buttons); static screens/modals in `client/index.html` inline the same paths directly
- User-chosen content icons are explicitly out of scope and untouched: `CLASS_ICONS` (the emoji picker for personalizing a class) and any place a class's own `cls.icon` is displayed
- Literal keyboard-key glyphs (e.g. `⌫`, arrow keys inside `<kbd>` in the shortcuts modal) and typographic in-sentence arrows (e.g. "Term → Definition" pill label, "Image↔Def" format badge) are intentionally left as Unicode text — they represent a physical key or a text separator, not an interactive icon
- Added missing `title`/`aria-label` to every icon-only button that lacked one during the pass (16 modal-close buttons, kebab "more options" menus, MCQ remove-distractor button)
- Theme matches KnowledgeApp's palette, softened for long reading: light mode uses KnowledgeApp's near-colourless stone greys a shade dimmer (`#f4f3f0` page, `#fcfbf9` surfaces, `#e0dcd5` hairlines, no pure white) with its brown accent (`#8b5a2b`); borders are 1px and the search bar is an outlined field rather than a filled one; dark mode is a neutral charcoal (`#1c1c1c` page, `#262626` surfaces) rather than near-black, with the brown kept only in the accent (`#e4b58b`). Text sits around 12:1 instead of 17:1+, and every text token stays ≥4.5:1 on every surface and tint. The flipped card back has its own `--card-back*` tokens, lighter than the surface in dark mode so it still reads as a separate face. Every colour comes from the `:root`/`[data-theme="dark"]` tokens in `client/style.css`; the formerly hardcoded indigo sidebar highlight and search bar, and the slate flashcard back, now use tokens or warm equivalents. The browser focus ring and checkbox/radio accents follow `--primary`. Stored class colours are untouched, but every place that paints one (card stripe, list colour bar, progress fill, class icons in the grid and sidebar) shows it desaturated to 60% (`--class-filter`) so it sits on the neutral page. In dark mode the class card or list row under the pointer, with keyboard focus or selected, and the hovered sidebar class, light up about two Tailwind steps lighter at full saturation (`--class-filter-hot`: `brightness(1.4) saturate(1.05)`, a 0.25 s fade); on a touch screen, with no hover, they stay muted. In dark mode the due badge is full amber (`#f0ac1c`) with dark text, and the class and lesson accuracy pills use the theme's own success/warning/danger colours instead of the light theme's 600 shades
- Colour theme picker in Preferences: Parchment (default), Sage, Slate, Sepia, Plum, Harbour, plus nine well-known editor schemes (the set Monkeytype also offers): Serika, Nord, Gruvbox, Solarized, Catppuccin, Rosé Pine, Everforest, Tokyo Night, Dracula. Most of those exist in one mode only; the other mode is derived from the same hues. Independent of Light/Dark/Match device; each palette defines both modes and swaps only the neutrals, the accent and the flashcard back, so success/danger/warning keep their meaning. Previews live and reverts on Cancel like the light/dark choice; stored as `preferences.palette` per account and applied from the localStorage cache before first paint (`data-palette` on `<html>`). Every pill shows its palette's page colour and accent. The browser `theme-color` follows the current palette and mode
- Dark mode follows Material/Apple practice in every palette: off-white text (~88% lightness, not pure white) and the palette's accent and success/danger/warning held to moderate saturation, so long sessions do not glare
- High contrast switch in Preferences (dark mode only): near-white text, the accent saturated to a neon, and neon success/danger/warning and grade buttons, on the same charcoal surfaces. It brightens both faces of the flashcard: the front's `--text`/`--text2` and the back's `--card-back-text`/`--card-back-dim`. Stored as `preferences.highContrast` (default off), applied before first paint as `data-contrast="high"` on `<html>`, previewed live and reverted on Cancel like the palette
- Soft buttons: primary, success, danger and warning buttons (including the four grade buttons) use a light tint of their colour with the colour as text. The tint is a small share of the hue mixed into the current palette's surface, so it leans cool in Harbour and warm in Parchment, instead of a deep fill under white text. Confident is an emerald, brighter than Know It's sage, so the grades step up red → amber → sage → emerald. Emphasis follows Material's ladder: the one action a screen exists for (Start Studying, a dialog's Save, Sign In) is filled; selected pills, the view toggle and the auth tabs are tonal (accent tint, accent text); hovering a pill gives a neutral wash rather than the selected look. Small count badges and the avatar keep a solid fill
- Dark-mode contrast fixes: `.quiz-opt`/`.tf-answer-btn` now set an explicit `color: var(--text)` — previously relied on the browser's default disabled-button text color, which Chromium dims to ~30% opacity and is effectively invisible on the tinted correct/wrong backgrounds in dark mode
- Mobile (≤600px) touch targets: `.icon-btn` grown to 40×40px and always visible (was hover-only, unreachable on touch); `.screen-title` reserves 55% width so header action icons wrap to a second row instead of truncating the class/lesson name to "…"; `.lesson-due-label` no longer wraps mid-word
- App-wide animation smoothness sweep: every screen navigation (class/lesson/study/dashboard, Back, sidebar, edge-swipe-back, browser Back) now fades/slides in instead of hard-cutting, via a pure-CSS `@starting-style` transition on `.screen.active` — zero call-site changes to `showScreen()`'s ~35 callers, and a no-op progressive enhancement on browsers that don't support `@starting-style` yet. Every modal and dropdown menu gets the same fade/scale-in on open (close stays instant, deliberately not animated — see `docs/decisions.md`). The 6 different "bar fills in to show a percentage" widgets (study/quiz progress, class/lesson mini progress, dashboard/stats/analytics fill bars) now share one duration/easing and animate via `transform: scaleX()` instead of layout-triggering `width`, through a shared `scaleXStyle()` JS helper. `prefers-reduced-motion: reduce` now collapses every transition/animation in the app (CSS- and JS-driven alike) to near-instant. Fixed a real bug found along the way: swipe-grading a flashcard could flash the just-graded card back into view before the next card's content was ready, and (a second bug introduced mid-fix, caught in review) un-flipping a card could briefly animate instead of snapping instantly, both now fixed via a shared `resetFlownOffScene()` helper with the correct reset ordering

## First-run tutorial
- Authenticated server-mode accounts see a short, dismissible, five-step tour after preferences load; it covers organizing classes/lessons, adding cards, studying, reviewing progress, and managing vocabulary selections for KnowledgeApp. Skip, Finish, close, Escape, and backdrop dismissal all mark it as seen so it does not interrupt again
- Completion is stored in the existing per-account preferences JSON (`tutorialCompleted`), with a user-namespaced local fallback if the request fails. No schema change, setup choice, or completion gate; Preferences includes a “Show tutorial” action for unlimited replay without resetting the first-run flag
- The tutorial is localized in English and Vietnamese and does not appear in local/offline mode, unauthenticated screens, or public-share views

- Create/edit/delete classes (icon, color)
- Class icon picker uses 16 minimalist line-art SVG icons (matching the app's feather-style icon system), each with its own fixed accent color for at-a-glance distinguishability; classes created before this redesign (which stored one of the old 16 emoji) render correctly via a render-time legacy-emoji→icon-key fallback map, no DB migration needed
- Create/edit/delete lessons (term↔def, MCQ, True/False, or Image↔Def format)
- Opening a new lesson always resets the format picker, so canceling or closing lesson editing cannot leave format choices disabled
- Bulk import via pipe-delimited text (MCQ: `question | correct | wrong1 [| wrong2 | wrong3 | wrong4]`; T/F: `statement | true` or `statement | false [;; explanation]`)
- AI prompt guide with copy button; AI generates 2–4 distractors per card; length rule relaxed — options should be comparable but natural phrasing takes priority over exact word-count matching
- Bulk delete lessons: "☑ Select" on class screen enters select mode with checkboxes, select-all, and "Delete selected" to remove multiple lessons and their cards at once
- Bulk delete cards: "☑ Select" on lesson screen enters card select mode with checkboxes, select-all, and "Delete selected" to remove multiple cards at once
- Deleting a card, lesson, or class frees its card storage but keeps your study history: study time, heatmap, streak, accuracy, reviews-today and new-card pace all stay unchanged (per-class/lesson breakdowns drop the deleted items). Delete confirmations say so. Implemented by dropping the `attempts.card_id → cards` FK; orphaned attempts also survive full-account export/import
- Lesson list re-render (after add/edit/delete/sort/filter) swaps old and new items atomically instead of clearing then repopulating after a network round trip — keeps scroll position stable instead of jumping to the top
- Pin a class (pin icon among the class card's hover buttons, or "Pin Class" in the class-detail ⋮ menu; on phones only the menu, so the always-visible card buttons stay at three): pinned classes sit at the top of Home in the order they were pinned and ignore the sort and its direction; the rest sort below them as usual. A small pin marks them before the name. Stored as `classes.pinned_at` (ms), restored from a full backup, not copied when a class is shared. `sortClasses()`, `toggleClassPinned()`, `tests/class-pin.test.js`
- Archive a class (🗄️ icon on the class card, or "Archive Class" in the class-detail ⋮ menu): archived classes are hidden from the home list, sidebar, and level slicer by default; an "🗄️ Archived" toggle pill next to the grid/list view switch shows only archived classes (with an "Unarchive" action) when active
- Archived classes are excluded from dashboard summary counts, "due for review," streak-relevant struggling-lesson detection, and analytics lesson breakdown — but remain fully browsable and studyable on demand if opened directly (their due badges still work inside their own lesson list)
- Export/import round-trips the archived flag; class-sharing clones always start unarchived
- Class level (optional, set in the class editor, also the default Home sort key) is shown in the meta line on both Grid and List views ("Lv 3 · 11 lessons") — previously used only for sorting, never displayed anywhere
- Long unbroken card text (e.g. a Definition pasted with no spaces) wraps instead of blowing out the lesson card list's page width (`.card-term`/`.card-def` gained `word-break`/`overflow-wrap`)
- Class (course) tags: comma-separated free text on each class (normalized — trimmed, lowercased, deduped, capped at 10), shown as chips on class cards (Grid + List, below the meta line); a tag filter/slicer on Home (separate from, and composes with, the existing Level filter) narrows the class list by tag; Global Search also matches class tags, not just names. Works in both server and local/offline mode. Tags survive export/import round-trips and class-share cloning. (Tags briefly lived at the lesson level first — moved to classes per feedback that course-level tagging matters more)
- AI "Suggest tags" (server mode only, requires `ANTHROPIC_API_KEY`): a button next to the tags field in the Edit Class modal (only shown for an existing class — a new one has no cards yet to analyze) sends a sample of the class's own card content to Claude (`claude-opus-5`) and suggests 1-6 subject/topic tags, merged into whatever's already typed rather than overwriting it. Server-side: `POST /api/classes/:id/suggest-tags`, rate-limited to 15/hour/user, capped at the first 60 cards (300 chars/field) to bound token cost, 45s request timeout, structured JSON output via `zodOutputFormat` so the response always matches the expected shape, suggested tags routed through the same `normalizeTags()` the manual-entry path uses. The button (and its server-side gate) is entirely absent when `ANTHROPIC_API_KEY` isn't configured or in local/offline mode — first AI-API-backed feature in the app, unlike the existing copy-paste "AI prompt guide"
- Export flashcard content (server mode only) at three scopes — one lesson ("Export" in the lesson ⋮ menu), one class ("Export" in the class ⋮ menu), or multiple classes at once (an "Export" button in Home's "☑ Select" multi-select bar, enabled once at least one class is checked). Downloads a human-readable JSON file (class name/color/icon/level/tags → lessons → cards' format+data; no internal ids/timestamps/sort_order), distinct from the pre-existing full-account backup (`GET /api/export`, unscoped, pairs with `POST /api/import`) which this doesn't touch. `GET /api/export/flashcards?lessonId=|classId=|classIds=a,b,c`, own rate-limit bucket (30/hour/user) separate from the full-backup one (10/hour/user). Filenames use the export's own name (lesson title, class name, or "flashcards-export" for the multi-class case) and are Unicode-safe end to end — server sends an RFC 6266 `Content-Disposition` (ASCII fallback + `filename*=UTF-8''...`), client reads the header itself and drives the download via a Blob + `<a download>` (not `window.location.href`, which would crash the SPA to a bare JSON page on any error status)
- Archive multiple selected classes from Home's existing multi-select bar; the action confirms the selected count, updates each owned class through the existing archive API semantics, clears selection after full success, and keeps the selection active with a localized error if any update fails
- Import flashcard content (server mode only): an "Import" button on the Home header (next to "Select") opens a file picker for a previously-exported flashcards JSON file and always creates brand-new class(es)/lesson(s)/cards from it — no merge-into-existing option, purely additive, so an import can't overwrite or collide with anything already in the account. `POST /api/import/flashcards`, own rate-limit bucket (30/hour/user, separate from both the flashcard-export bucket and the full-account import's). Validates the whole file before writing anything (one bad card aborts the entire import, nothing partially created) and re-derives level/tags/color from the raw import data the same way the manual class-creation path does — a hand-edited or otherwise untrusted file can't smuggle a non-numeric level, an unbounded/uncased tag list, or (closing a stored-XSS path into the class-card renderer) a non-hex color value

## Spaced Repetition
- Per-card SRS intervals: 10min → 1h → 4h → 1d → 3d → 7d → 21d (step advances on correct, resets on wrong)
- Due badges on lesson cards showing count of cards due for review
- "Quick quiz · N due" button on the lesson screen (and the Dashboard's "Due for review" rows) launches a quiz on the due cards only, capped by Max reviews per day; the label and tooltip say it's a quiz so it isn't mistaken for a flashcard review
- Due counts on class cards (home screen) and dashboard grouped by class
- Dashboard due lessons grouped by class with clickable rows to launch review
- Spaced repetition scheduler: FSRS (Free Spaced Repetition Scheduler, `ts-fsrs`) — each card tracks its own stability/difficulty/state rather than sharing one fixed interval ladder with every other card. Quiz-mode correct answers are rated Hard rather than Good, so recognition earns a shorter next interval than an equivalent Flashcard-mode recall, by construction of the algorithm — the direct successor to the old step-ceiling clamp. Existing per-card progress was preserved via a one-time migration (see `docs/decisions.md`)
- **Quiz answers count as Know It** preference (off by default): when on, for every card a correct quiz answer is graded like a flashcard Know It — FSRS Good, card marked known (so lesson/class progress moves), no recognition-cap hint, and dropped from Needs Recall — and a wrong answer like Still Learning (reset, marked not known). Confident is never reached from a quiz. The Quiz mode hint in Study Setup switches to describe the setting. Off keeps the rule that cards only make progress through flashcards
- "Needs Recall" filter on Study Setup (right after "Due Only"): surfaces due cards whose most recent correct answer came from quiz recognition, never from actively recalling them in Flashcard/Recall mode, so cards only weakly confirmed can be proactively cleared in one batch rather than discovered piecemeal during Quiz sessions. Selecting it auto-switches Mode to Flashcard (still overridable) since quiz mode can't confirm active recall by definition
- Flashcard interval preview: the 4 grading buttons show how long until the card comes back if graded that way, precomputed server-side from the live FSRS scheduler (not duplicated client-side) so the preview always matches what actually happens
- Memory Interval Distribution chart (Dashboard, deliberately not named after the underlying algorithm — end users don't need to know it's FSRS): buckets cards by FSRS state (Learning/Relearning get their own bucket) and interval range, using the same perceptual boundaries (10m/1h/4h/.../1yr) the old step-based chart used. Respects the 7/30/60/90-day period pill (scoped to cards last reviewed in that window) like every other chart in its section — initially shipped ignoring the pill entirely, fixed same day, see `docs/decisions.md`

## Performance
- Bulk cards endpoint (`POST /api/cards/by-lessons`): multi-lesson quiz startup reduced from 2N+1 HTTP requests (N `getCards` + N `getKnownMap` per lesson) to 2 requests total regardless of lesson count; 10-lesson quiz goes from 21 requests to 2 (90% reduction)
- Per-card correlated subquery for `last_studied_at` replaced with a single `GROUP BY` aggregate JOIN on the attempts table
- Added `idx_states_user_due ON card_states(user_id, srs_due_at)` and `idx_attempts_cu_created ON attempts(card_id, user_id, created_at)` indexes for faster SRS queries
- `GET /api/classes/:classId/lessons`: the single query joining `lessons → cards → attempts` with aggregates forced SQLite to fan every card out across all its attempts before grouping, causing multi-second latency for classes with heavily-attempted lessons. Split into three smaller queries (lessons, then per-lesson `last_modified_at`/`last_interacted_at` batch-loaded and merged in JS) — see `docs/decisions.md` for why the attempts query needs `CROSS JOIN` rather than plain `JOIN`
- `GET /api/lessons/:lessonId/cards`, `POST /api/cards/by-lessons`, `GET /api/stats/lesson/:id`: same category as the classes/lessons fix above — the `last_studied_at` LEFT JOIN aggregated the requesting user's *entire* attempt history (not just the cards being requested) before joining down. Replaced with a batched `card_id IN (...)` lookup (chunked at 500 IDs to stay under SQLite's bound-variable cap); `/stats/lesson/:id` needed no extra query at all since the existing per-card attempts fetch already had the data — see `docs/decisions.md`

## Reliability & Operations
- `GET /health`: trivial DB-connectivity check, rate-limited (60/min/IP). Wired into `railway.toml`'s `healthcheckPath` — gates new deploys (Railway won't cut traffic to a deploy that fails it) but does **not** monitor an already-live instance; see `docs/decisions.md` for why that distinction mattered
- Event-loop watchdog (`server/middleware/watchdog.js`): since `node-sqlite3-wasm` is synchronous, one heavy DB call blocks every concurrent request on the process. The watchdog force-exits if the event loop is unresponsive past a threshold (default 20s, `WATCHDOG_MAX_LAG_MS`), turning a hang into a crash that `railway.toml`'s `restartPolicyType` actually reacts to. Uses a monotonic clock (`process.hrtime`), not wall-clock time, so a host clock jump can't falsely trigger it
- Rate limiting (`server/middleware/rateLimit.js`) on login, register, forgot-password, reset-password, and the Google OAuth callback — in-memory per-IP, no external dependency, consistent with the app's existing single-process architecture
- Request logging to stdout (`server/middleware/requestLog.js`): method, matched **route pattern** (never the raw path/query string — several routes carry secrets directly in the URL), status, duration; requests over 2s are tagged `[SLOW]`
- Auth POST bodies capped at 10kb (scoped to `/api/auth`, separate from the general 10mb JSON limit) so a large body can't be fully parsed — itself a blocking cost — before a route's rate limiter gets a chance to reject it
- `share.js`'s `getClassData()` (backing the public `GET /api/share/view/:token`, plus class cloning) batched instead of one query per lesson — same N+1 category as the `cards.js`/`stats.js` fixes, extracted into a shared `server/lib/batch.js` helper on its second occurrence
- Rate limiting extended to every other heavy/synchronous route: `GET /api/export`, `POST /api/import`, `POST /api/share/clone/:token`, `POST /api/share/clone-invite/:classId` (all keyed by user, not IP — an IP-keyed limiter on an authenticated route lets unrelated accounts on a shared office/campus network exhaust each other's quota), and the public `GET /api/share/view/:token` (IP-keyed, since there's no session to key by; capped well above plausible simultaneous traffic from one shared link)
- Answers survive a bad connection: a grade, quiz answer or known-state write that can't reach the server (offline, 15s timeout, 408/429/5xx gateway errors, expired session, or a non-JSON 200 from a captive portal) is kept in `localStorage["fc-pending-writes:<userId>"]` and replayed in order on reconnect, at login, and before the next answer. A toast says answers are being kept, and another says how many synced. Each attempt carries a `clientId`; `POST /api/attempts` skips one it has already recorded and writes the attempt plus its schedule in a single transaction. A repeated plain 500 drops the write after 5 tries so it can't block the queue
- No native `alert()`/`confirm()`: validation in form dialogs appears under the field that needs fixing (focused, cleared on typing); other messages are toasts (`showToast`); yes/no questions use the app's confirm dialog. Archive/unarchive, multi-archive, bulk add, bulk import and sign-out confirm themselves with a toast
- Save buttons (class, lesson, the four card formats, bulk add, bulk import) disable and read "Saving…" while the request runs, so a double tap or Ctrl/Cmd+Enter can't create duplicates; a failed save shows a toast and keeps the modal and its input open
- gzip/brotli response compression — biggest win on `GET /api/export`, which can run several MB as JSON for a long-lived account; runs off the main thread (zlib's async binding), so it doesn't reintroduce the blocking risk the rest of this reliability work addresses

## Study
- Flashcard mode (flip, mark known/learning)
- In server mode, select an English word or phrase on either visible side of a study card — or, in Quiz mode, in the question, the explanation, or any answer option once the question is answered (selecting pauses the auto-advance and shows Next) — and choose **Save as English word**. FlashcardApp queues the selection with its card context; KnowledgeApp's **Fetch words** action or `ka vocabulary` uses the configured OpenRouter model to create an English definition and example, then syncs a card into the **English Vocabulary → Saved Words** lesson. Sentence selections are treated as context for choosing a useful headword; saved requests stay pending until KnowledgeApp completes them. On a phone the flashcard's **Save as English word** chip floats just above the sticky grade row (`placeVocabularySelectionAction()`), because in its place below the card it sat behind the grades, where it could not be seen or tapped
- The **Vocabulary** sidebar inbox shows pending captures and their context. Add words or phrases manually with optional context, or delete pending entries before KnowledgeApp fetches them
- Saving a word twice with the same context is refused (409, `duplicateWordQueued` or `duplicateWordFetched`): the selection button reads "Already saved with this context" or "Already in your vocabulary deck", and the Add word dialog says to add a different context. The same word with a different context is saved, since it may be another meaning. Matching ignores case, extra spaces and punctuation around the word; a save with no context matches any earlier save of the word. Pending requests and completed ones whose card still exists count; delete the card and the word can be saved again (`server/lib/vocabularyDup.js`, `tests/vocabulary-dup.test.js`)
- Vocabulary terms ending in a space and slash-delimited IPA (for example, `resilient /rɪˈzɪliənt/`) show the headword prominently with the IPA beneath it on the study-card front. The stored term stays unchanged; terms without trailing IPA retain their existing display
- Fixed: moving to a new card while the previous one was still flipped (common after grading + auto-advance) animated the un-flip with the new card's content already loaded, briefly revealing its answer mid-rotation; the reset is now instant, not animated
- "Flashcard & Write" study mode (Study Setup's 3rd Mode pill, alongside Flashcards and Quiz): shows a text input on the card front, auto-focused on every new card so typing needs no click first — type a guess, flip (click or Enter) to see it echoed as "Your answer: ..." above the back content for self-comparison. The typed text is never checked; grading is still driven only by the 4 mark buttons, except that using a hint caps the grade at Hard (below) — same cards, same SRS behavior as plain Flashcard mode, just this one difference. Not the same as the removed Recall mode (a separate self-grading study mode) — never writes to attempts/SRS beyond the normal Flashcard grading. Was a Preferences toggle (off by default, hidden unless discovered) before becoming its own mode — see `docs/decisions.md`
- Undo the last grade (Anki's Undo): after any flashcard grade a pill at the bottom of the screen reads "Marked Confident · Undo" for 6 seconds, in thumb reach but just above the grading buttons (which stick to the bottom on phones), so it never covers them; Undo, or `Ctrl/⌘+Z` while the pill is up, brings the card back ungraded, even from the session summary when it was the last card. The answer is gone, not reversed: `DELETE /api/attempts/:id` removes the attempt row and writes back the card's FSRS fields from `attempts.prev_state`, a snapshot taken when the answer was recorded (`{"row":null}` for a first answer, `{"notDue":true}` when the answer changed no schedule), so streak, daily goal and accuracy count it as never given. The server refuses (404/409, code `undoExpired`) an attempt that is not the card's latest, is older than 10 minutes, or predates the column; the client then shows "That grade can no longer be undone" and changes nothing. The attempt id is made on the client (the same `clientId` the offline queue already sends), and the DELETE goes through the same queue, so offline the answer and its undo replay in order. The known flag goes back too, to `NULL` for a card never marked, which `PUT /api/cards/states/:id` now accepts. Session time and the time-left median give the answer's seconds back. ## Cram for a test
- **Cram** card order in Study Setup (flashcards only; picking Quiz switches it off): lessons interleaved, hardest first within each; a missed card comes back 3 cards later, a recalled one 8; a card leaves the round after 3 correct answers (Hard counts). Progress counts cards at their goal rather than queue position, the dots are hidden, and undo takes a repeat back out of the queue. The not-due hint is not shown, since nearly every repeat is not due
- Answers in cram go to the scheduler as usual; a repeat of a card that is not due yet is recorded without moving its schedule, so drilling cannot push FSRS intervals around
- **Cram for a test** (server mode only): select lessons in a class and choose Cram for a test, then name it and set the date and time. The cram screen shows a countdown, a readiness bar (cards answered in the cram and not missed in the last finished round), and the next round. Rounds are spaced at 15% of the time left, between 20 minutes and a day ("Next round at 19:40", and you can start early). Round 1 asks 3 correct answers per card; later rounds ask 1, or 2 for a card missed in the round before
- Within 12 hours of the test a round is a **final review** of up to 20 cards already seen, most-missed first, and nothing new. From 22:00 to 05:00 with the test under a day away, the screen says sleep will help more than another round
- Home lists active crams above everything else (name, countdown, rounds done). A cram is archived a day after its test; End cram archives it sooner. Cards and their progress are never touched
- Progress is not stored: `GET /api/crams/:id/progress` counts each card's right and wrong answers since the cram began, so undo, offline replays and studying outside cram mode all count. A round is recorded (`PATCH /api/crams/:id {round:{missed}}`) only when finished; the cards it missed set the next round's goals (`server/routes/crams.js`, `tests/cram.test.js`, `tests/crams-route.test.js`)

## KnowledgeApp Sync (server mode only)
- Vocabulary capture: **Fetch words** in KnowledgeApp (or `ka vocabulary`) fetches pending words from FlashcardApp, enriches each with an English definition and example using the configured OpenRouter model, and saves completed cards to **English Vocabulary → Saved Words** in FlashcardApp. Before fetching, the FlashcardApp **Vocabulary** sidebar inbox lets the user add a word with optional context or delete a pending request
- KnowledgeApp pushes semantic card changes (rewritten, removed, restored, split) to your account; the matching cards update automatically and are flagged "Updated — needs review" (or "Removed from source") so you know to look again
- Updated cards keep their previous content: "Show previous" on the lesson card list compares old vs new; "Mark reviewed" dismisses the flag, and answering or editing the card dismisses it too
- A reworded card you had already studied becomes due now, but keeps its FSRS stability/difficulty — it isn't reset to a brand-new card; cards you never studied stay new
- A split in KnowledgeApp adds the new cards right after the original in the same lesson
- KnowledgeApp can merge its cards into classes you built yourself, without losing progress: it reads your class, links cards that mean the same thing to its own (so later changes flow in), and adds the cards you don't have yet — right after a related card, or into a new lesson of that class. KnowledgeApp shows you a preview before anything is written
- A new lesson added this way appears first under the default "date added" lesson sort
- Deleting a card KnowledgeApp created tells KnowledgeApp it was not worth studying: its next Sync or Fetch removes that card's source from the book (restorable there) instead of adding it back
- Deleting a whole lesson of KnowledgeApp cards means "stop studying these": KnowledgeApp keeps the cards' sources but no longer syncs them back. - Match highlighted in blue within result titles; breadcrumb shows class name (lessons) or class › lesson (cards)

## Mobile PWA & Swipe Gestures
- Long-press a class, lesson or card (half a second) to start multi-select with that item already selected; ordinary taps then add or remove items, and the usual select bar (select all, study, export, delete) appears. A press that moves — a scroll — does not select, and the tap that ends the press never opens the item. Touch screens only; with a mouse, use "☑ Select" or `X`
- PWA icons: `apple-touch-icon.png` (180px, full-bleed for iOS), `icon-192.png`, `icon-512.png` generated from logo SVG via Playwright at build time
- `manifest.json` with `display: standalone`, `theme_color: #f4f3f0` (the page background; dark mode sets `#1c1c1c` at runtime), `background_color: #16150f`
- Meta tags: `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `theme-color`, `apple-touch-icon`
- Flashcard swipe: drag `#fc-scene` horizontally; right swipe (> 75px) = Know It, left swipe = Learning; card flies off screen with rotation then triggers the mark; short swipe (< 75px) snaps back with spring animation
- Swipe hint labels (green "Know It" / red "Learning", reusing the same `study.knowIt`/`study.learning` i18n keys as the grading buttons) fade in as drag distance grows toward threshold; rotate ±15° like Tinder labels
- Long-press-to-copy on a card no longer gets misread as a swipe: the `touchmove` handler checks `window.getSelection().type === "Range"` and defers to an active native text selection entirely (un-arming an in-progress drag if a selection starts mid-gesture), rather than disabling text selection on the card
- `touch-action: pan-y` on `.fc-scene` — browser owns vertical scroll, JS owns horizontal swipe
- Edge back swipe: start from x < 30px, swipe right > 90px → triggers back button for current screen, or opens the sidebar on Home; excluded on flashcard screen (handled by card swipe instead)
- A separate non-passive `touchmove` listener on the leftmost 24px calls `preventDefault()` on a recognizably horizontal drag, attempting to suppress iOS's own native edge-swipe-back gesture in that same zone (a long-standing WKWebView quirk, active even in installed/standalone PWAs) — see decisions.md for the back-and-forth on this; effectiveness is unconfirmed on real devices
- Search modal: swipe down > 80px closes it (the listener looked up a non-existent `#search-modal` and never attached until 2026-10-04; `tests/ux-audit.test.js`)
- Fixed (WebKit-specific): List view's hover-only class actions (edit/archive/delete) stayed in the layout flow at `opacity:0` on touch, silently eating ~124px from the row; a class with both a due-badge and an accuracy pill could squeeze the title down to one character per line. Actions are now `display:none` below 600px (still reachable via the class's ⋮ menu)
- Fixed: the SRS interval preview text on Flashcard grading buttons (`· 10m` etc.) sat inline after the label, adding to the button's width rather than its height, which could push the 3-button row past a narrow viewport (`white-space:nowrap` blocks flex-shrink below content width). Initially worked around by hiding it on mobile; properly fixed by wrapping it onto its own row inside the button (`flex-wrap` + `flex-basis:100%`) so it adds height instead — re-enabled on mobile now that the root cause is fixed
- Fixed: pull-to-refresh only checked vertical drag distance, so a diagonal edge-swipe (opening the sidebar) could also cross its threshold and fire a spurious refresh + spinner on top of the sidebar animation; now bails if the gesture is more horizontal than vertical
- Fixed: lesson titles in Class Detail were ellipsizing mid-word even at realistic lengths — measured at 375px, the title box only got 123px of a 351px row because padding/gap/format-badge crowded out the space, not the deliberately-always-visible edit/delete icons (M13). Tightened mobile padding/gap and hid the format badge (still visible once the lesson is opened) to give the title the room back — the reported example now fits fully
- Fixed: sidebar class names had a `title` attribute for a tooltip that never fires on touch (no `:hover`), so a truncated name had no way to be read at all on mobile. Switched from ellipsis-truncate to wrap — the row's `min-height` (not a fixed height) lets it grow to 2 lines

## Haptic Feedback (Android)
- Short vibrations on the moments that carry meaning, through one `haptic(name)` helper with a seven-pattern vocabulary: `tick` (10ms — flip, prev/next, shuffle, dot jump, quiz navigation, edge-swipe back, search-modal swipe-close, pull-to-refresh commit, swipe threshold crossed, swipe cancelled), `select` (18ms — grading a card, long-press multi-select), `success` (24ms — quiz correct, forced-retype match, LaTeX confirm), `warn` (30ms — forced-retype drill begins), `error` (`[12,70,12]` — quiz wrong, retype mismatch), `danger` (`[24,50,24]` — confirming a delete), `complete` (`[18,60,18,60,36]` — flashcard session summary, quiz results)
- Keyboard shortcuts share the same buzzes for free: 1–4, Space/Enter and the quiz number keys all go through the same functions the taps do
- The swipe threshold buzz is one-shot per gesture (latched, so jitter at the boundary can't rattle), and a swipe that crossed the threshold and was then pulled back buzzes once more to say the grade was cancelled
- Session-end buzzes fire once per session: the quiz one is gated on every card having actually been answered, so deleting the last card or paging past the end of the review doesn't celebrate
- Preferences → "Vibration feedback", on by default, stored per account like the other preferences. Enabling it buzzes once as a sample; that preview deliberately doesn't take effect until Save, since an invisible setting left behind by Cancel would silently disagree with what was saved
- Answer sounds: a two-note marimba strike (C5→E5) when a quiz answer or a Flashcard & Write retype is right, a single low knock (G3) when it is wrong. Synthesized with Web Audio through one `playSound(name)` helper, so there are no audio files. Flashcard self-grades (Learning … Confident) stay silent, since those are the user's own judgement. Preferences → "Sound effects", on by default (`preferences.sounds`); enabling it plays a sample without changing state until Save. On Safari 17+ the audio session is `ambient`, so the iPhone silent switch mutes it; older iOS ignores the switch. Chosen by the user from five previewed sets (soft chime, marimba, bright, minimal tick, bell). After a lock, the app switcher or a call, iOS leaves the context `interrupted` (not `suspended`, which was all that got resumed), and a context back from the background can report `running` and still be silent; so any non-running state is resumed, and on `visibilitychange` to visible or a `pageshow` from the back-forward cache the context is closed and rebuilt on the next answer. The same return cancels the speech queue, which WebKit can leave stuck so every later `speak()` waits behind it. `tests/sounds.test.js`
- iOS has no Vibration API at all (Safari and every WKWebView, installed PWAs included), so this is Android-only in practice; on desktop the call is a harmless no-op. The toggle stays available everywhere — preferences sync across devices — with a hint line explaining the limitation, shown only on browsers that can't vibrate

## Recall Mode (removed)
- Recall mode was removed; historical attempt records with `source='recall'` are preserved in the DB
- Dashboard: the Overall Accuracy bar (with its Quiz/Flashcard pills) and the Card Difficulty Breakdown are removed. The Study charts above them already show accuracy (the headline row and the weekly Accuracy line) and how settled cards are (Intervals, Grades), so the two sections repeated them in a weaker form; the difficulty levels were a blend of lifetime and last-five error rates that no other part of the app uses. `/api/stats/dashboard` no longer computes `diffBreakdown` (a pass over every card's attempts) and `/api/stats/analytics` no longer returns `accuracyBySource`
- *(Superseded by the removal above.)* The Overall Accuracy source-pill breakdown no longer surfaces a "Recall" pill even when an account has legacy `source='recall'` attempts (initially it did, to preserve visibility into old data — reversed per user feedback that recall isn't a mode anymore and shouldn't appear as one); those attempts still count toward the aggregate accuracy number and total, just not their own pill
